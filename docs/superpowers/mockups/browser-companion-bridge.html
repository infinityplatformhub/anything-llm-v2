Browser Companion — ให้ agent กด Chrome ตัวจริงของคุณ

ต่อ extension เดิม (browser-extension/) เข้ากับ chrome.debugger แล้ว agent ในแอปสั่งกด/พิมพ์/อ่านหน้าเว็บได้ — เป็น Chrome จริง profile จริง cookie จริง ไม่มี automation flag ให้ antibot จับ

ทางเดินของคำสั่งหนึ่งครั้ง

ลองสลับสถานะ

สามอย่างที่ popup นี้ต้องทำได้

  • allowlist ปิดหมดก่อน — ถ้าไม่มีอันนี้ agent สั่งได้ทุกแท็บที่คุณ login ค้าง ธนาคาร อีเมล รวมด้วย
  • สลับมือได้ — captcha / OTP มาถึง agent หยุด คุณกดเอง แล้วสั่ง ทำต่อ
  • log ย้อนดูได้ — ทุกคำสั่งที่เข้าเบราว์เซอร์บันทึกไว้ ไม่ใช่แค่ผลลัพธ์
ปุ่ม ตัดทุกแท็บ อยู่ทุกหน้าไม่ใช่แค่หน้าเดียว — เวลาจะหยุดคุณไม่ควรต้องหาว่ามันอยู่แท็บไหน

ช่องคุยระหว่าง server กับ extension — เลือกหนึ่ง

แนะนำ

WebSocket ค้างไว้

  • เร็ว — agent กด 30 step ติดกันไม่สะดุด
  • ไม่แตะ schema ใช้ API key เดิม
  • server รู้ทันทีว่า browser ออนไลน์ไหม
  • ราคา: MV3 service worker ตาย idle 30 วิ ต้องเขียน keepalive + reconnect · server จำ socket ไว้ใน memory หลาย replica ต้อง sticky (dev2 replica เดียว ยังไม่เจ็บ)
ทางเลือก

Long-poll queue

  • ไม่มี state ค้างใน server กี่ replica ก็ได้
  • service worker ตายแล้วตื่นมา poll ต่อได้เลย
  • ราคา: ช้าขึ้น 0–500ms ต่อ step งานยาวรู้สึกได้ · ต้องมีตาราง queue ใน DB = แตะ schema ต้องขออนุมัติแยก

ข้อจำกัดที่แก้ไม่ได้ — ไม่ใช่ bug

01แถบ "DevTools is debugging this tab" โผล่ทุกแท็บที่ attach — Chrome บังคับ ซ่อนไม่ได้
02chrome://* และ Chrome Web Store attach ไม่ได้ — Chrome กันไว้
03Web Store review เข้มมากกับ debugger permission — น่าจะต้องแจกแบบ unpacked / enterprise policy ไปก่อน
04LinkedIn ToS ห้าม automate ทุกแบบ — ความเสี่ยงอยู่ที่ บัญชี ไม่ใช่โค้ด เป็นการตัดสินใจของคุณ

E2E test ของแอปเราเอง — ขอตัดออกจากงานนี้

localhost ไม่มี antibot ให้ผ่าน Playwright headed + gate-e2e เดิมตอบได้ครบแล้ว ถ้าเอา bridge นี้ไปทำ E2E จะได้ test ที่พึ่ง Chrome บนเครื่องคุณ — รันใน CI ไม่ได้ ค่าใช้จ่ายมาทีหลังตอนอยากให้ CI รันเอง บอกได้ถ้าอยากให้รวม
