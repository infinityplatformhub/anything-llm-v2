# Executive-grade layouts for `create-pptx-presentation`

**Date:** 2026-09-08 · **Status:** direction approved in chat (mix: data-forward page structure,
editorial cover/closing, warm KPI tiles, data-forward palette)

## Problem
The agent tool `create-pptx-presentation` (`server/utils/agents/aibitat/plugins/create-files/pptx/`)
can only emit title / section / bullet / table slides. A real executive report built with it
(INFI_Executive_Report_2569.pptx, 19 slides) had zero charts, every number dumped as bullets, half
the deck as empty divider slides, and an "AnythingLLM" watermark on every page. The user rejected it
as unfit to send to executives. Skills/prompts cannot fix this: the tool schema has no chart slot.

## Goal
A deck generated through AnythingLLM chat reads as a board-ready executive report: real PowerPoint
charts, KPI tiles with semantic status, a strong cover and closing, one idea per slide, Thai and
English set in one typeface, no watermark. Reference renders (built with the same pptxgenjs the
tool uses, approved as the design ceiling):
`docs/superpowers/mockups/pptx-directions/preview-{1-editorial,2-data,3-warm}.png`.

## Non-goals
- Native waterfall charts (PowerPoint has none via pptxgenjs); bridge = signed bar with pos/neg colors.
- Images, icons, animations, custom master slides.
- Correctness of the numbers the model feeds in (period alignment etc.) — that is the data tool's job.
- Rewriting docx/pdf/xlsx renderers beyond removing their watermark.

## Design decisions (from the three directions)
| aspect | choice | from |
|---|---|---|
| content page structure | action title = full-sentence conclusion (26pt bold, max 2 lines), one visual ~70% of slide, one 14pt note/footer line, 0.75pt hairlines, no cards | data-forward |
| cover + closing | full-bleed dark ground, 2-line headline 48-60pt that states the verdict, company/period 14-16pt | editorial |
| KPI | 2×2 (or 1×3 / 1×4) solid tone tiles, number 40pt+, delta 18-20pt on a light pill in semantic color, prev-value 12pt | warm |
| palette (default theme) | ink `141414`, muted `6E7377`, hairline `D6D9DB`, accent deep teal `0F4C5C`, dark ground `0F1B1F`; semantic good `1E7A4B` warn `8A6100` bad `B3261E`; series ramp 5 steps of teal | data-forward |
| type | one face for Thai+English on every run: `Leelawadee UI` (Windows), falls back to Thonburi/Sarabun on macOS; minimum 11pt for chart labels, 14pt body | all |
| watermark | removed from pptx, docx, pdf, xlsx (`getLogo` callers + "Created with"/"Generated by" strings) | user |

The other four existing themes (`corporate`, `dark`, `minimal`, `creative`) keep their identity but
gain the new token groups below so every layout renders on every theme.

## Theme tokens added (`themes.js`)
`ground` (dark full-bleed color), `groundText`, `groundMuted`, `hairline`, `tileColors[4]`,
`pillBg`, `good`, `warn`, `bad`, `series[5]`, `fontFace` (replaces `fontTitle`/`fontBody`
pair — one face; the old two keys stay readable for compatibility).

## New slide layouts (schema of `submit-section-slides`, `section-agent.js`)
All existing fields stay. `layout` enum grows from `section | content | blank` to:

- `cover` — reserved for the tool (not for the section agent); rendered from `title` + optional
  `headline` (2 lines max) + `subtitle`. The old title slide becomes this.
- `kpi` — `title` (action title) + `kpis[2..4]` of `{ label, value, unit?, delta?, status?: good|warn|bad, note? }`.
- `chart` — `title` + `chart: { type: bar|column|line|area|pie|doughnut|bridge, categories[], series[{ name, values[] }], valueFormat?, highlight?: number[] (indexes drawn in accent), note? }` + optional `note` (footer line).
  `bridge` = single-series signed bar; values > 0 green, < 0 red, first/last accent.
- `two-column` — `title` + `chart` (as above, left ~55%) + `points[2..4]` (right).
- `statement` — full-bleed dark ground, `headline` (≤ 2 lines, 48pt), `subtitle`; used for closing and for section dividers (replaces the near-empty `section` layout; `section` stays as an alias).
- `content` and `table` unchanged; `blank` removed from the agent's enum (kept in renderer).

Validation: renderer rejects a `chart` with mismatched `categories.length` vs every
`series.values.length`, or `kpis` outside 2..4, by falling back to `content` with the raw numbers
and logging — a deck must still be produced.

## Renderer (`utils.js`, pptxgenjs 4.0.1, LAYOUT_16x9 10×5.625in)
- Every chart sets explicitly: `chartColors`, `showLegend` (only when >1 series), `showValue`
  with `dataLabelFontSize` 11-12, `catAxisLabelFontSize` 12-13, `valGridLine: {style:"none"}`,
  `valAxisLineShow:false`, `catAxisMajorTickMark:"none"`, `chartArea.fill`/`plotArea.fill` =
  slide ground (charts on dark slides otherwise punch a white hole), `layout` (manual plot area)
  so shapes can be positioned against the plot.
- Per-point colors only work for single-series `bar`; `highlight` and `bridge` rely on that.
- Doughnut: `holeSize` 60-65, total in the hole via `addText`.
- Keynote fix: pptxgenjs 4.0.1 writes `ref="A1:B9'"` (stray `'`) into the embedded xlsx
  `xl/tables/table1.xml`; Keynote then renders the chart empty (upstream #1306/#1396, PR #1327).
  The tool post-processes the written buffer: unzip, strip the quote in every
  `ppt/embeddings/*.xlsx` table part, re-zip. PowerPoint is unaffected either way. Covered by a test
  that asserts the fixed ref pattern in the embedded xlsx.
- Watermark: delete `addBranding` (pptx), `applyBranding` (pdf/xlsx), footer logo cell (docx),
  and `getLogo` if no caller remains. `pptx.company` stays "AnythingLLM" in metadata only.

## Section-builder prompt (`section-agent.js`)
Replace the rules block with:
- 1–3 slides per section; one idea per slide; the title is the conclusion (a sentence with the number in it), not a topic.
- Any list of 3+ numbers over time/categories MUST be a `chart`; a set of 2–4 headline metrics MUST be `kpi`; bullets are for arguments, max 3 per slide, ≤ 12 words each.
- Never emit a `section`/`statement` slide that only repeats the next slide's title.
- Use `note` for source / period / caveat, one line.
The `create-pptx-presentation` tool builds `cover` from `title` + `headline` (new optional param,
"the one-sentence verdict") and appends a `statement` closing from a new optional `closing` param.

## Tests (jest, `server/__tests__/utils/agents/aibitat/plugins/create-files/pptx/`)
Renderer tests build a real pptx into a buffer, unzip with `jszip` (already a pptxgenjs dep), and assert XML:
1. `kpi` layout → 4 tiles, number runs ≥ 40pt, delta color equals theme `bad` for `status:"bad"`.
2. `chart` bar with `highlight:[6]` → 8 `<c:dPt>`, index 6 = accent; no `<c:majorGridlines>`.
3. `bridge` → negatives red, positives green, first/last accent.
4. `two-column` → one chart part + text on the right half (x ≥ 5in).
5. `statement`/`cover` → full-slide rect with theme `ground`, headline ≥ 48pt.
6. Invalid chart (length mismatch) → falls back to content, still 1 slide, no throw.
7. Keynote fix → embedded xlsx table `ref` has no `'`.
8. No slide/chart part contains "Created with", "AnythingLLM" (except docProps), for pptx; docx/pdf/xlsx: the branding string absent from output.
9. Schema: `submit-section-slides` enum contains the new layouts; `blank` absent.
10. Every theme has every new token key (guards `getTheme` fallbacks).
Plus a preview script (`test-themes.js`, already exists) extended with one deck exercising all
layouts per theme, run manually for the visual check.
